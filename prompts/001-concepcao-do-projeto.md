- **Data:** 29/10/2026
- **Agente / Modelo:** Gemini 1.5 Pro / Antigravity
- **Objetivo:** Explicar o contexto do Lab DIO, formalizar a proposta inicial de entregáveis e solicitar análise crítica e sugestões de melhoria.

---

## 📥 Prompt Enviado

```markdown
Este é o repositório https://github.com/digitalinnovationone/lab-natty-or-not do curso 'Natural ou Fake Natty? Como Vencer na Era das IAs Generativas' da DIO. Ele é um template para que eu faça um fork e desenvolva o meu projeto a partir dele. O objetivo deste repositório, além de ser o entregavél do curso, é ser um portifólio profissional para o aluno e uma documentação rica sobre o uso de inteligência artificial generativa na criação de conteúdo digital.

Mais especificamente preciso demonstrar o meu processo de criação de conteúdo assistido por IA, documentando a reflexão crítica e o resultado final. O entregável esperado inclui um README com registro do projeto e com os entregáveis, como por exemplo e-book, vídeo, podcast, etc.

Resumindo, o fluxo típico é: escolher um formato de conteúdo, usar IA para roteirizar e criar o material, documentar o processo e apresentar um resultado final.

Minha proposta inicial é a criação de um e-book:

- Tarefa 1: Definição do tema 
- Tarefa 2: Criação das imagens
- Tarefa 3: Seleção das ferramentas
- Tarefa 4: criação do e-book

Obs: Após a conclusão da etapa "e-book", penso em avançar com um video promocional com avatar, e depois um podcast.

Análise críticamente, forneça feedback com sugestões de melhorias e retorne em formato markdown.
```

---

## 📤 Resposta da IA

> ### 🔍 Análise Crítica do Prompt Original
> Como engenheiro de prompts, no geral, o seu prompt original já é muito bom porque contextualiza bem o cenário (o lab da DIO), define o escopo inicial (e-book + capa) e traz uma divisão inicial de tarefas.
> No entanto, para extrair o máximo de uma IA ao iniciar um projeto assistido, podemos aplicar técnicas modernas de estruturação de prompts: **Definição de Persona, Clareza de Contexto, Restrições e Formato de Saída Estruturado**.
>
> **Pontos Fortes:**
> - Excelente contexto (links dos repositórios original e do fork).
> - Escopo criativo claro e alinhado com o desafio "Natty or Not".
>
> **Oportunidades de Melhoria:**
> - Falta de Persona: A IA não sabe exatamente quem ela deve ser (ex: mentor técnico, copiloto criativo, etc.).
>
> ### 🚀 Sugestão de Prompt Otimizado
> ```markdown
> # Contexto

> - Repositório base: https://github.com/digitalinnovationone/lab-natty-or-not
> - Meu repositório (fork): https://github.com/heviane-learning/lab-natty-or-not
> 
> # Papel
> Aja como meu Mentor Técnico e Co-piloto de Inteligência Artificial Generativa, especializado em criação de conteúdo, estruturação de portfólios no GitHub e engenharia de prompts.
> 
> # Objetivo do Projeto
> Desenvolver um projeto de portfólio para um E-book gerado por IA (com tema definido), e uma documentação completa em Markdown no README.md do meu repositório.
> 
> # Plano de Execução (Tarefas)
> - Tarefa 1: Escolha do tema central + Definição do prompt/ferramenta para a imagem de capa.

- **O que foi aproveitado:**
  - Adoção formal do papel de **Mentor Técnico e Co-piloto** para o assistente de IA.
  - Divisão das tarefas em etapas bem delineadas (Tema ➔ Ferramentas ➔ Conteúdo ➔ README).
- **Decisão de Tema Tomada:**
  - Dentre as opções levantadas para o e-book, foi selecionado o tema: **"Engenharia de Software Natty: Boas Práticas, Limites e Antipatterns com IA"**, alinhando o desafio ao meu background de engenharia de software tradicional.
- **Resultado do Experimento:**
  - Prompt inicial aprovado como base de contexto para os próximos passos.
